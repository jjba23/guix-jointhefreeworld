=guix-jointhefreeworld= is a [[https://guix.gnu.org/manual/en/html_node/Channels.html][GNU Guix channel]]:
a package collection that Guix can pull alongside its own.  It is not a fork of
Guix, and it is not an operating system.  It is a small, signed, readable
collection of packages for the software written around
[[https://jointhefreeworld.org][jointhefreeworld]] — the Guile libraries the
projects share, the command-line tools they ship, the Emacs packages that make
them pleasant to work with, and the builder that publishes the web site itself.

The official Guix channel already carries some of these projects, but at
whatever revision it last imported.  This channel follows each project's own
release tag, so one pull gives you the latest versions together, with the
dependencies and launchers they were tested with.

** Who it is for
:PROPERTIES:
:CUSTOM_ID: who-it-is-for
:END:

- *Guix users* who want the newest =maak=, =ggg=, =iter-vitae=,
  =mutastructura=, or =emacs-modusregel= without writing package definitions.
- *Scheme hackers* building on [[https://codeberg.org/jjba23/kracht][Kracht]],
  [[https://codeberg.org/jjba23/scriba][Scriba]],
  [[https://codeberg.org/jjba23/veritas][Veritas]],
  [[https://codeberg.org/jjba23/hygguile][Hygguile]], or the rest of the stack.
- *Emacs users* who want the jointhefreeworld packages installed the Guix way.
- *Builders and writers* who publish with =maak=, =iter-vitae=, =ggg=, or the
  jointhefreeworld site builder.
- *The simply curious*: it is a small, readable example of how to package a
  Lisp-flavoured software collection for Guix.

** What you get
:PROPERTIES:
:CUSTOM_ID: what-you-get
:END:

A single channel containing:

- the *Guile libraries* the projects are assembled from;
- the *command-line programs* that build, test, migrate, generate, and deploy;
- the *Emacs packages* for editing, testing, and looking at Emacs;
- *lambdock*, a GTK4 Wayland dock you can reprogram while it runs;
- *heks-bash*, a Bash configuration generated from Scheme;
- the *jointhefreeworld site builder*, which turns Org sources into the published
  static site.

The full catalogue, with versions and entry points, is
[[#package-catalogue][below]].

* Why you'll like it
:PROPERTIES:
:CUSTOM_ID: why-you-ll-like-it
:END:

- *Latest releases, not leftovers.*  Each package follows its project's release
  tag.  When a new tag is published, the channel is updated; =guix pull= brings
  it to you.
- *One channel, the whole stack.*  The libraries, the tools, the Emacs packages,
  and the site builder are versioned together, so the pieces you install are the
  pieces that were tested together.
- *Authenticated, not merely downloaded.*  The channel is signed with OpenPGP.
  Guix verifies every commit it fetches against the maintainer key in
  [[file:.guix-authorizations][=.guix-authorizations=]]; see [[#authentication-and-security][Authentication and security]].
- *Reproducible by content.*  Every source is pinned by a SHA-256 hash.  A moved
  tag fails the build instead of silently changing what you install.
- *Commands that just work.*  Program launchers are wrapped with the Guile and
  the libraries they need.  =guix install maak= gives you a working =maak=; you
  do not need to keep a =guix shell= open.
- *Emacs-native.*  The Emacs packages install into Guix's Emacs load path and
  are ready for =require=.
- *Plain Guix inside.*  Every definition is an ordinary =package= form — an
  =origin=, a build system, arguments, inputs — written the way the Guix
  repository writes them.  There is no channel-specific macro to learn.
- *Safe by construction.*  No deployment secrets, session keys, database files,
  or =env.scm= files live here.  The Artanis web services that need them are
  deliberately run from their own checkouts.
- *Small enough to audit.*  A handful of package modules, a manifest, a Maak
  file, and a signed history.  You can read the whole thing over a coffee.

** Install as a channel (recommended)
:PROPERTIES:
:CUSTOM_ID: install-as-a-channel-recommended
:END:

Append the channel to your channel list, keeping Guix itself:

#+begin_src scheme
  ;; ~/.config/guix/channels.scm
  (cons* (channel
          (name 'jointhefreeworld)
          (url "https://codeberg.org/jjba23/guix-jointhefreeworld")
          (branch "trunk")
          (introduction
           (make-channel-introduction
            "b0ac3f05075d7959860fc9e1db5871acddea3986"
            (openpgp-fingerprint
             "83BC 6E1C 8726 B8C2 97F8  D16E 24F4 6738 CE11 4AF6"))))
         %default-channels)
#+end_src

The =introduction= is the root of trust: it names the first signed commit and
the key that signed it, so Guix can verify every commit that follows.  Keep it
unless you have a reason not to; without it Guix can still fetch the channel,
but it cannot authenticate what it fetched.

Then pull once and install what you need:

#+begin_src sh
  guix pull
  guix install maak ggg iter-vitae mutastructura
#+end_src

A sample, not a limit: =guix install= takes any number of package names.  For
the Emacs side:

#+begin_src sh
  guix install emacs-maak emacs-modusregel emacs-veritas
#+end_src

Check that the channel is there:

#+begin_src sh
  guix describe
#+end_src

You should see =jointhefreeworld= next to =guix=, at a commit on =trunk=.

** Try a checkout without pulling
:PROPERTIES:
:CUSTOM_ID: try-a-checkout-without-pulling
:END:

A checkout is enough for trying a package, reading the definitions, or hacking
on the channel:

#+begin_src sh
  git clone https://codeberg.org/jjba23/guix-jointhefreeworld
  cd guix-jointhefreeworld

  # Build or install one package from the checkout
  guix build -L channel maak
  guix install -L channel maak

  # Build or enter the whole collection in one go
  guix build -L channel -m manifest.scm
  guix shell -L channel -m manifest.scm
#+end_src

=-L channel= adds the channel's module directory to Guile's load path.  That is
what makes =(jointhefreeworld packages)= resolvable before the channel has been
pulled.  The checkout workflow does not authenticate anything; use it for
development, and use the channel when you want the signed history.

** Verify the channel
:PROPERTIES:
:CUSTOM_ID: verify-the-channel
:END:

=guix pull= authenticates automatically when the =introduction= is present.
If you want to check a checkout by hand:

#+begin_src sh
  guix git authenticate b0ac3f05075d7959860fc9e1db5871acddea3986 \
    "83BC 6E1C 8726 B8C2 97F8  D16E 24F4 6738 CE11 4AF6"
#+end_src

That verifies every commit from the introduction to =HEAD=.  If it succeeds,
the history you are about to build is the history the maintainer signed.

** Update, pin, or remove
:PROPERTIES:
:CUSTOM_ID: update-pin-or-remove
:END:

#+begin_src sh
  # Update the channel and your packages
  guix pull
  guix upgrade

  # See what changed in the channel
  guix describe
#+end_src

To pin the channel to a particular revision, give the channel a =commit= in
your =channels.scm= instead of a =branch=.  To pin Guix itself as well, use
=guix time-machine= with the same channels file.  To remove the channel, delete
its entry, run =guix pull= again, and =guix remove= the packages you installed.

** Command-line programs
:PROPERTIES:
:CUSTOM_ID: command-line-programs
:END:

Every program installs a command in =bin/=.  The launchers are wrapped with the
Guile and the libraries they need, so these work directly after =guix install=.

| Command                                                                           | What it does                                    |
|-----------------------------------------------------------------------------------+-------------------------------------------------|
| =maak --list=                                                                     | List the tasks in the nearest =maak.scm=.       |
| =ggg -f glyphs.scm -d dist=                                                       | Render the badges described in a Scheme file.   |
| =iter-vitae -f cv.scm -d dist=                                                    | Generate a CV from a Scheme description.        |
| =lenkesamler -f bookmarks.scm=                                                    | Collect, check, and convert bookmarks.          |
| =skapa -n my-project -t o -l GPL=                                                 | Scaffold a new project from a template.         |
| =araneola --url https://example.org=                                              | Crawl a site and write a sitemap.               |
| =mutastructura --database sqlite3 --connection app.db --migrations db/migrations= | Apply pending SQL migrations.                   |
| =caco list=                                                                       | List the desktop tasks in =cask-and-cons=.      |
| =jointhefreeworld-build=                                                          | Build the site in the checkout you run it from. |
| =jointhefreeworld-serve=                                                          | Serve =./public= on port 50011.                 |

A few of these deserve a word:

- =maak= is the command runner the other projects use.  Tasks are ordinary
  Scheme: no DSL, no generated build step.  If you already have a =maak.scm=,
  =maak --list= is the front door.
- =mutastructura= applies migrations transactionally and records what it applied
  in a =migrations_history= table.  Running the same directory twice is safe;
  =status= and =validate= let you look before you leap.
- =araneola= follows links breadth-first, stays on the host it was given, and
  respects =robots.txt=.  The sitemap is written atomically.
- =cask-and-cons= needs a =Cask and Cons= file, which is where its named desktop
  tasks live.

** A tiny Maak example
:PROPERTIES:
:CUSTOM_ID: a-tiny-maak-example
:END:

If you have never used =maak=, a task file is just a Scheme module:

#+begin_src scheme
  ;; maak.scm
  (define-module (maak)
    #:declarative? #t
    #:use-module (maak maak))

  (define (hello)
    "Say hello from Guile."
    ($ '("echo hello from Scheme")))
#+end_src

Then:

#+begin_src sh
  maak hello
  maak --list
#+end_src

The channel's own [[file:maak.scm][=maak.scm=]] is a larger example: =maak check= lints,
builds, and authenticates this repository.

** Guile libraries
:PROPERTIES:
:CUSTOM_ID: guile-libraries
:END:

The libraries are ordinary Guile packages; install the ones you need and import
their modules.  The short version:

#+begin_src scheme
  (use-modules (kracht prelude)
               (scriba scriba)
               (veritas veritas)
               (bewaking bewaking)
               (hygguile hygguile))
#+end_src

Each package keeps its own manual; the table in [[#guile-libraries][Guile libraries]] says what it
is for.  Some starting points:

#+begin_src scheme
  ;; Kracht: a friendlier standard library
  (use-modules (kracht prelude))

  ;; Scriba: structured logging
  (use-modules (scriba scriba))
  (log-info "hello from Scriba")

  ;; Veritas: tests with an embedded DSL
  (use-modules (veritas veritas))
#+end_src

** Emacs packages
:PROPERTIES:
:CUSTOM_ID: emacs-packages
:END:

The Emacs packages install into Guix's Emacs load path.  Require the ones you
want and enable the modes you like:

#+begin_src emacs-lisp
  (require 'maak)          ; M-x maak-run-task
  (require 'modusregel)    ; M-x modusregel-mode
  (require 'veritas)       ; M-x veritas-mode
  (require 'welkomscherm)  ; M-x welkomscherm
  (require 'tekengrootte)  ; M-x tekengrootte-set-scale

  (modusregel-mode 1)
  (tekengrootte-set-scale 'large)
#+end_src

- =maak.el= discovers the =maak.scm= of the project a buffer belongs to, reads
  the exported tasks and their lambda lists, and runs one with its arguments
  gathered in the minibuffer.
- =modusregel= is a clean, fast mode line with Eglot and Flymake indicators.
- =veritas.el= teaches Emacs the vocabulary of the Veritas test framework and
  runs tests from the project, file, or test at point.
- =welkomscherm= is a quiet welcome screen and dashboard.
- =tekengrootte= makes face sizes proportional to one adjustable scale.

** The channel entry
:PROPERTIES:
:CUSTOM_ID: the-channel-entry
:END:

The channel specification has four fields worth knowing:

| Field          | What it does                                                                                                           |
|----------------+------------------------------------------------------------------------------------------------------------------------|
| =name=         | The name Guix uses for the channel.  Keep =jointhefreeworld= so the commands in this README match.                     |
| =url=          | The repository Guix fetches.  Use the Codeberg URL above.                                                              |
| =branch=       | =trunk= tracks the latest signed commit.  Replace it with =commit= to pin a revision.                                  |
| =introduction= | The trust anchor: the first signed commit and its signing key.  Omit it only if you accept an unauthenticated channel. |

To pin a revision, replace =branch= with =commit= and keep the introduction:

#+begin_src scheme
  (channel
   (name 'jointhefreeworld)
   (url "https://codeberg.org/jjba23/guix-jointhefreeworld")
   (commit "4856480b0ff083a321b0cca9852346ef3a3b1892")
   (introduction
    (make-channel-introduction
     "b0ac3f05075d7959860fc9e1db5871acddea3986"
     (openpgp-fingerprint
      "83BC 6E1C 8726 B8C2 97F8  D16E 24F4 6738 CE11 4AF6"))))
#+end_src

The commit above is an example, not a promise; use the commit =guix describe=
reports after a pull.

** Emacs packages
:PROPERTIES:
:CUSTOM_ID: emacs-packages-2
:END:

The Emacs packages are ordinary libraries after installation.  A few knobs
worth knowing:

#+begin_src emacs-lisp
  ;; Where maak.el finds the command runner
  (setq maak-executable "maak")

  ;; The mode line
  (modusregel-mode 1)

  ;; A proportional type scale
  (tekengrootte-set-scale 'large)
  (add-hook 'tekengrootte-set-scale-hook
            (lambda () (message "scale is now %s" tekengrootte-scale)))

  ;; Welkomscherm runs a hook before it renders
  (add-hook 'welkomscherm/pre-render-hook
            (lambda () (message "drawing the dashboard")))
#+end_src

Each package's own README documents the rest: =veritas-mode= binds its commands
under =C-c v=, =modusregel= has a customization group of the same name, and
=welkomscherm= exposes its sections as a list you can edit.

** The site builder
:PROPERTIES:
:CUSTOM_ID: the-site-builder
:END:

=jointhefreeworld-build= reads =CI= to decide whether absolute URLs point at
=localhost= or at the real host, and =jointhefreeworld-serve= reads =PORT=:

#+begin_src sh

=maak.scm=.  It does not need a running server.

* Authentication and security
:PROPERTIES:
:CUSTOM_ID: authentication-and-security
:END:

A channel is code you run.  This one is set up so you can tell where it came
from.

** The trust chain
:PROPERTIES:
:CUSTOM_ID: the-trust-chain
:END:

- =.guix-authorizations= lists the OpenPGP key whose signatures are accepted.
- =.guix-channel= names the =keyring= branch and the primary URL.
- The =introduction= in =channels.scm= pins the first signed commit and the key
  that signed it.
- The =keyring= branch contains the matching public =.key= file.

Guix verifies each fetched commit against the authorizations of its parent.  The
introduction is the one commit it cannot verify that way, so it verifies the
introduction's signature directly against the fingerprint you pinned.

The introduction is:

#+begin_src scheme
  (introduction
   (make-channel-introduction
    "b0ac3f05075d7959860fc9e1db5871acddea3986"
    (openpgp-fingerprint
     "83BC 6E1C 8726 B8C2 97F8  D16E 24F4 6738 CE11 4AF6")))
#+end_src

If you omit it, Guix can still pull the channel, but it will warn that it cannot
authenticate it.  Include it unless you have a reason not to.

** What is verified
:PROPERTIES:
:CUSTOM_ID: what-is-verified
:END:

- *The history.*  Every commit in the channel's authenticated history is signed
  by an authorized key.
- *The sources.*  Every package origin carries a SHA-256 hash.  A moved tag
  produces a hash mismatch, not a silent change.
- *The result.*  Guix builds in its daemon, in isolated build environments, from
  the sources and inputs the definitions name.

** What is deliberately absent
:PROPERTIES:
:CUSTOM_ID: what-is-deliberately-absent
:END:

- No =env.scm=, session keys, tokens, database files, or deployment credentials.
- No Artanis web services.  Those are deployment applications: they need a
  writable working tree, a database, and a deployment's own secrets, so they are
  run from their own checkouts.
- No vendored binaries or generated build outputs.

* Project layout and tasks
:PROPERTIES:
:CUSTOM_ID: project-layout-and-tasks
:END:

The repository is one module per kind of package:

#+begin_example
  .guix-channel                    channel metadata and primary URL
  .guix-authorizations             keys whose signatures are accepted
  manifest.scm                     every package, for `guix build -m'
  channels.scm                     an example channel list with the introduction
  HACKING.org                      updating, adding, publishing, authenticating
  README.org                       this file
  maak.scm                         the repository's tasks
  assets/                          the banner used above
  channel/                         the directory declared in .guix-channel
    jointhefreeworld/
      packages.scm                 imports and re-exports all packages
      packages/
        guile.scm                  the Guile libraries
        applications.scm           the command-line programs
        emacs.scm                  the Emacs packages
        misc.scm                   heks-bash and lambdock
        site.scm                   the jointhefreeworld site builder
#+end_example

Every definition is an ordinary Guix package: an =origin=, a build system,
=arguments=, and inputs, written the way packages are written in the Guix
repository itself.  There is no channel-specific macro to learn.

The repository has a [[file:maak.scm][=maak.scm=]].  With Maak installed,
=maak --list= shows the tasks; the ones used most are:

| Task                     | What it does                                                      |
|--------------------------+-------------------------------------------------------------------|
| =maak build=             | Build every package in the manifest.                              |
| =maak build maak=        | Build one package.                                                |
| =maak fmt=               | Run =guix style= over the Scheme sources.                         |
| =maak lint=              | Lint every package, including network checks.                     |
| =maak check=             | Lint offline, build every package, then authenticate the history. |
| =maak shell=             | Enter a shell with the whole collection.                          |
| =maak authenticate=      | Verify the signed history from the introduction to HEAD.          |
| =maak show-introduction= | Print the introduction for a =channels.scm=.                      |
| =maak publish=           | Push =trunk= and the =keyring= branch to Codeberg.                |

See [[file:HACKING.org][HACKING.org]] for the longer version: updating a package to a new release,
adding a package, creating the keyring branch, and the signing rules.

** Before you send a patch
:PROPERTIES:
:CUSTOM_ID: before-you-send-a-patch
:END:

Run the checks the repository uses:

#+begin_src sh
  maak fmt
  maak check
#+end_src

=maak fmt= formats the Scheme sources with =guix style=.  =maak check= lints
without the network, builds every package, and authenticates the commit history.
If you change a package, also run =maak lint= for the network-backed checks (the
updater and CVE checks).

** Signed commits
:PROPERTIES:
:CUSTOM_ID: signed-commits
:END:

Channel authentication works by signing commits.  If you are sending a patch that
will be committed to this repository, sign it:

#+begin_src sh
  git config user.signingkey <your-key>
  git config commit.gpgsign true
  git commit -S
#+end_src

The rules and the keyring procedure are in [[file:HACKING.org][HACKING.org]].  If you are sending a
patch by email or a pull request from a fork, the maintainer can sign it on the
way in; just say so.

* What is not packaged, and why
:PROPERTIES:
:CUSTOM_ID: what-is-not-packaged-and-why
:END:

These projects live in the same account but are not in this channel:

- *Artanis web services* — byggsteg, lucidplan, pingwing, wikimusic, torikomi —
  are deployment applications.  They read a tree of controllers, views, pages,
  and configuration from their working directory and write a database, logs, and
  compiled modules beside themselves, so they are run from their own checkouts
  with their own =env.scm= and database.  A package cannot carry a deployment's
  keys or its data.
- *symbanta* is a Spring Boot application built with Maven.  A reproducible
  package needs every Maven artifact as an input, and the tree is not vendored;
  packaging it means packaging that repository first.
- *symbanta-dashboard* is a Vite/React application whose dependencies come from
  npm; the same objection applies, and the build also wants the whole
  =node_modules= tree.
- *free-alacarte* is a Haskell library; it is not part of this channel.
- *heks-emacs*, *heks-linux*, and *wolk-jjba* are personal configurations — an
  Emacs configuration, a GNU/Linux distribution, and a Guix system definition —
  rather than programs to install.  They are used by cloning them, not by
  installing them.
- *private-notes* and *static-assets* are data, not software.
- *wolkenschloss* has no public repository at the time of writing, so there is no
  URL a channel could fetch it from.

* FAQ
:PROPERTIES:
:CUSTOM_ID: faq
:END:

** Is this an official GNU Guix channel?
:PROPERTIES:
:CUSTOM_ID: is-this-an-official-gnu-guix-channel
:END:

No.  It is a personal/community channel maintained by Josep Bigorra.  It follows
Guix's channel format and authentication rules, but it is not part of Guix.

** Why not just submit everything to Guix?
:PROPERTIES:
:CUSTOM_ID: why-not-just-submit-everything-to-guix
:END:

Some of these packages are in Guix already, at older revisions.  This channel
exists so the latest releases can be used together without waiting for the next
import.  Upstreaming is welcome; a package that lands in Guix can still stay
here for the release cadence.

** Do I have to authenticate the channel?
:PROPERTIES:
:CUSTOM_ID: do-i-have-to-authenticate-the-channel
:END:

It is strongly recommended.  Without the =introduction=, Guix can fetch the
channel but cannot verify it; it will warn.  With it, every commit is checked
against the maintainer key.

** Does it work on Guix System and on a foreign distribution?
:PROPERTIES:
:CUSTOM_ID: does-it-work-on-guix-system-and-on-a-foreign-distribution
:END:

Yes.  A channel is a package collection, not a system service.  Any Guix that
can pull channels can use it.

** What about other architectures?
:PROPERTIES:
:CUSTOM_ID: what-about-other-architectures
:END:

The Guile and Emacs packages are architecture-independent Scheme and Emacs Lisp.
=lambdock= needs GTK4 and Wayland.  If something fails on your architecture,
please open an issue with the output of =guix describe= and the build log.

** How do I pin a revision?
:PROPERTIES:
:CUSTOM_ID: how-do-i-pin-a-revision
:END:

Give the channel a =commit= instead of a =branch= in =channels.scm=.  To pin
Guix as well, use =guix time-machine= with the same channels file.

** How do I remove the channel?
:PROPERTIES:
:CUSTOM_ID: how-do-i-remove-the-channel
:END:

Delete its entry from =channels.scm=, run =guix pull= again, and =guix remove=
the packages you no longer want.
